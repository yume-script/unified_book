# 📚 통합 도서 검색

BookOasis 미디어 서버에서 코어 수정 없이 메타데이터 검색과 라이브러리 관리를 안정적으로 지원하는 통합 도서 검색 플러그인 패키지입니다. 알라딘, 국립중앙도서관(Seoji), 구글의 도서 데이터를 스레드 풀(Thread Pool) 기반으로 병렬 조회하여 높은 신뢰도의 도서 정보를 고속으로 완성합니다.

> ⚠️ **네이버 도서 API 지원 종료**: 네이버 Open API가 정상 동작하지 않아 관련 연동 코드를 전부 제거했습니다(`naver.py` 삭제, `NAVER_ID`/`NAVER_SECRET` 설정 항목 삭제). 현재는 **알라딘 / 국립중앙도서관 / 구글** 3개 소스만 사용합니다.

---

## ✨ 주요 특징 (Key Features)

| 기능 | 설명 |
| :--- | :--- |
| **⚡ 병렬 소스×축 검색** | 알라딘·국립중앙도서관·구글 도서 API를 `ThreadPoolExecutor`로 동시에 백그라운드 호출합니다. `isbn`/`title`/`author` 3개 검색 축과 소스를 조합해서 병렬로 실행합니다. |
| **🏛️ 국립중앙도서관(Seoji) 연동** | 국립중앙도서관 Seoji API를 정식 소스로 추가했습니다. ISBN 축은 국립중앙도서관을 최우선 정본(canonical) 소스로 사용하고, 실패 시 알라딘 ISBN 조회로 폴백합니다. |
| **🎯 소스별 필드 한정 검색** | title/author/isbn 검색축마다 각 API의 정확한 필드 파라미터를 사용하도록 소스별로 함수를 분리했습니다. 예전에는 저자 축 검색도 제목 검색 함수를 그대로 재사용해서 결과가 비어 있는 문제가 있었습니다.<br>- 알라딘: `QueryType=Title` / `QueryType=Author` / `QueryType=ISBN`을 각각의 전용 함수(`search_aladin`, `search_aladin_author`, `search_aladin_isbn`)로 분리<br>- 구글: `intitle:`/`inauthor:`/`isbn:` 쿼리 연산자로 필드 한정<br>- 국립중앙도서관: title 우선 조회 후 결과 없으면 author로 자동 재시도 |
| **👥 저자별 개별 검색축** | 공저자가 여러 명(콤마 구분)인 경우, 하나의 문자열로 합쳐서 검색하면 각 API가 이름을 통째로 인식하지 못해 매칭에 실패합니다. 저자 1명당 별도의 `author` 축을 만들어 각각 검색합니다. |
| **🧹 저자 필드 정규화** | 국립중앙도서관/알라딘의 `AUTHOR` 필드가 `"저자 : 홍길동 ; 옮긴이 : 김철수 ;"`처럼 역할 라벨 + 세미콜론 형식으로 오는 경우, 역할 라벨을 제거하고 순수 이름만 콤마로 정리합니다(`옮긴이`/`역자`/`그림`/`삽화`/`감수`/`해설`/`편집` 등 비저자 역할은 제외). |
| **🚫 동명이인 오매칭 필터** | 저자 축 검색 결과 중, 찾고 있는 책 제목과 유사도가 낮은 항목(= 저자만 같고 전혀 다른 책)은 결과에서 자동으로 제외합니다. |
| **🔗 link 컬럼 기반 ISBN 역추적** | DB/파일에서도 ISBN을 못 찾은 경우, `books.link` 컬럼(알라딘/네이버 등 상품 URL)을 파싱해서 ISBN을 최종적으로 시도합니다. 쿼리스트링의 `ISBN`/`isbn` 파라미터를 우선 확인하고, 없으면 URL 전체에서 10/13자리 숫자열 후보를 뽑아 체크섬 검증을 통과한 값만 채택합니다. |
| **🧭 단어 경계 인식 매칭** | DB에서 책을 검색어로 역추적할 때, 단순 부분 문자열(substring) 매칭 대신 **단어 경계에서 시작하는 매칭**만 인정합니다. 예: `"성의 과학"`이 전혀 무관한 책 `"...불확정성의 과학을 열다..."`의 단어 중간에 우연히 걸리는 오매칭을 방지합니다. |
| **🗂️ DB 매칭 정확도 순 폴백** | 1) title/title_alias 완전일치 → 2) title/title_alias 단어 부분일치(경계 검사 포함) → 3) 최후 수단으로 파일명(디렉토리 경로 제외, 경계 검사 포함) 순으로 시도합니다. |
| **🏷️ title_alias 보호 저장** | `apply()` 시점에 기존 DB `title`과 새로 검색된 제목이 다르면, 원본 `title`은 그대로 두고 새 제목을 `title_alias`(표시용 별칭)에 저장합니다. 파일명 유래 title을 함부로 덮어쓰지 않습니다. 검색 축 구성 시에도 `title_alias`가 있으면 파일명 유래 title보다 우선 사용합니다. |
| **🔓 metadata_locked 강제저장** | 도서의 `metadata_locked`가 켜져 있어도 저장을 차단하지 않고 강제로 진행합니다(로그에 `강제저장=True`로 기록). |
| **🗑️ 삭제 도서 제외** | 모든 DB 매칭 쿼리에 `COALESCE(is_deleted, 0) = 0` 조건을 적용해, 삭제 표시된 도서는 매칭 대상에서 제외합니다. |
| **🖼️ 고해상도 커버 수집** | 원본에 가까운 표지 품질 확보를 위해 소스별 이미지 주소를 정제하여 가장 선명한 최고 화질의 커버를 다운로드합니다. |
| **🏷️ 정돈된 UI 레이아웃** | 소개글 본문(Description) 영역에 서지 정보를 중복 노출하지 않고, `출간일` 영역 끝자리에 `[ISBN: ...]` 값을 결합하여 한 줄로 출력합니다. |
| **🎯 정밀 매칭 원천 추적** | ISBN 정밀 검색 성공 시 어떤 경로로 도서를 식별했는지 타이틀 접두사로 구분하고, 끝에 별표(`*`)를 붙입니다.<br>- `[출처/ISBN]`: 입력값 자체가 ISBN<br>- `[출처/DB]`: 로컬 DB의 ISBN 기록<br>- `[출처/LOCAL]`: 책 파일(EPUB/PDF) 내부 판권지 직접 파싱<br>- `[출처/AI]`: 로컬 분석 실패 후 Gemini/LiteLLM AI가 본문 판독<br>- `[출처/LINK]`: `books.link` 컬럼의 URL에서 ISBN 파싱 |
| **🔐 기존 ISBN 데이터 보호** | 신규 검색 결과에 ISBN 정보가 비어 있는 경우에도, 기존 DB의 ISBN 값이 공백으로 덮어씌워져 지워지지 않도록 `COALESCE / NULLIF` 안전 쿼리를 수행합니다. |
| **📂 임포트 섀도잉 방지** | 다른 플러그인이나 코어에 `utils.py`가 존재하여 이름이 충돌하는 문제를 방지하기 위해 파일명을 `utils_unified.py`로 변경하고, **절대 경로 기준 동적 모듈 로드(`importlib`)** 방식을 도입했습니다. |
| **⚙️ DB Row 크래시 원천 차단** | 데이터베이스 게이트웨이가 반환하는 Row 객체에서 `.get()`을 직접 호출할 때 발생할 수 있는 `AttributeError` 예외를 감지하여, 안전하게 데이터 검색 및 저장 구문을 실행하는 내부 헬퍼(`get_row_val`)를 내장했습니다. |

## 🔍 검색 처리 흐름 (search 단계별 요약)

1. **1단계 · 로컬 파싱**: 입력값 자체가 유효한 ISBN인지 검사
2. **2단계 · DB/파일 파싱**:
   - DB에서 title/title_alias/file_path 기준으로 도서 매칭 (단어 경계 인식, 삭제 도서 제외)
   - DB에 ISBN이 없으면 EPUB/PDF 파일을 직접 스캔(판권지 파싱, 실패 시 AI 판독)
3. **2.5단계 · link 파싱**: 그래도 ISBN을 못 찾았으면 `books.link` 컬럼 URL에서 ISBN 파싱 시도
4. **정본 조회**: ISBN이 확정되면 국립중앙도서관 → 알라딘 순으로 ISBN 정밀 조회를 선행해서, 이후 title/author 검색축에 사용할 "정본" 제목/저자를 확보
5. **3단계 · API 병렬 호출**: isbn/title/author(저자별 개별) 축 × 알라딘/국립중앙도서관/구글 소스를 조합해 병렬 검색, 결과를 필터링(ISBN 일치 검증, 저자축 제목 유사도 필터 등)
6. **4단계 · 메타데이터 합성**: 같은 책을 가리키는 결과들을 ISBN/제목 기준으로 그룹핑하고, 소스 우선순위(알라딘 > 국립중앙도서관 > 구글)에 따라 하나로 병합·정렬
7. **5단계 · 저장(apply)**: 표지 다운로드, title/title_alias 분기 저장, metadata_locked 무시하고 강제 저장

## 💡 문서 내부 ISBN 정밀 역추적 기술

* **PDF 스캔 대역 및 인코딩 보완:**
  * 최근 단행본들의 목차나 머리말이 길어지는 트렌드에 발맞추어 스캔 대역을 **앞쪽 30페이지 및 뒤쪽 30페이지**로 대폭 확장하여 깊숙이 숨어있는 판권지(Colophon)를 안정적으로 찾아냅니다.
  * PDF 내부의 특수 유니코드 대시 기호(en-dash `–`, em-dash `—`, soft-hyphen `\u00ad` 등)와 구분 기호(`.`)를 분석 직전 표준 하이픈(`-`)으로 실시간 강제 치환하는 전처리를 적용하여 정규식 검출 누락을 방지합니다.
* **EPUB XHTML 엔티티 복원:**
  * EPUB 파일 조판 시 공백 줄바꿈 깨짐을 방지하기 위해 사용되는 웹 특수 공백 부호(`&nbsp;`, `&#160;` 등)를 온전한 공백 문자로 언이스케이프(Unescape) 처리하는 HTML 파서를 내장했습니다.
  * 판권지가 책 머리말(표지 직후) 영역에 있는 경우를 대비하여 **앞쪽 8개 책장 및 뒤쪽 8개 책장**을 동시에 이중 교차 분석합니다.
* **link 컬럼 URL 파싱:**
  * 파일 스캔으로도 ISBN을 못 찾으면, DB에 저장된 상품 URL(`books.link`)에서 쿼리스트링 파라미터 또는 체크섬 검증을 통과하는 숫자열을 찾아 ISBN으로 채택합니다.
* **단어 경계 인식 부분 일치 검색:**
  * 데이터베이스 내 도서명과 파일명이 미세하게 불일치하더라도 검색어의 앞 '두 단어'를 파싱하여 부분 일치 매칭하되, 단순 substring이 아니라 **단어 경계에서 시작하는 매칭만** 인정하는 3단계 백업 쿼리를 구동, 오매칭 없이 실제 파일 추적률을 유지합니다.
* **국립중앙도서관 → 알라딘 순 ISBN 정본 조회:**
  * ISBN이 확정되면 국립중앙도서관 Seoji에서 먼저 정밀 조회하고, 실패 시 알라딘 ISBN 조회로 폴백해서 title/author 검색축의 기준값을 확보합니다.
* **2단계 자동 백업 검색 (Fallback):**
  * ISBN 검색 결과가 0건이거나 실패한 경우 즉시 전처리 정제된 원래 책 제목 검색으로 Fallback 전환되어 신뢰할 수 있는 도서 검색 결과를 보장합니다.

## 📂 디렉토리 구조 (Directory Structure)

GitHub 배포를 위한 폴더 구조 구성은 다음과 같습니다. 이 플러그인은 카테고리 레벨 풀페이지 UI가 없는 순수 메타데이터 검색형 플러그인이므로, 설정 UI는 환경설정 탭 커스텀 폼 규격인 `settings.html`/`settings.css`를 사용합니다.

```text
plugins/metadata/unified_book/
├── __init__.py           # 플러그인 로드 진입점
├── unified_book.py       # 메인 코어 플러그인 (흐름 제어 및 DB 트랜잭션)
├── aladin.py              # 알라딘 검색 (Title/Author/ISBN 전용 API 분리)
├── nlk.py                 # 국립중앙도서관 Seoji 검색 (title→author 자동 폴백, ISBN 전용 API)
├── google.py               # 구글 검색 (intitle/inauthor/isbn 필드 한정 검색)
├── utils_unified.py      # 공통 유틸리티 (날짜 정제, 고화질 수집, 문서 파싱, DB 헬퍼, LLM)
├── settings.html         # 환경설정 탭 카드 내부 전용 커스텀 입력 폼 마크업
├── settings.css          # 환경설정 탭 카드 전용 입력 폼 스타일
└── VERSION               # 자동 업데이트 추적용 버전 파일
```

> `naver.py`는 네이버 API 미동작으로 제거되었습니다.

## 📦 설치 및 적용 가이드 (Installation)

1. `plugins/metadata/` 경로 하부에 `unified_book` 폴더를 생성하고 패키지 파일들을 배치합니다.
2. BookOasis 웹 UI의 환경설정 > 플러그인 메뉴에서 `통합 도서 검색` 활성화 스위치를 켭니다.
3. 필요한 API 키를 설정하고 저장을 누릅니다.
   - 알라딘 TTBKey (`ALADIN_KEY`)
   - 국립중앙도서관 Seoji 인증키 (`NLK_CERT_KEY`)
   - Google API Key (`GOOGLE_API_KEY`, 선택)
   - Gemini/LiteLLM API Key (`GEMINI_API_KEY`, 판권지 AI 판독용, 선택)
4. 책 상세 정보 수정 > 돋보기 아이콘(검색) 클릭 시 알라딘/국립중앙도서관/구글의 정돈된 검색 결과를 즉시 조회하실 수 있습니다.

## ⚙️ 설정 항목 (config_schema)

| 키 | 설명 | 필수 |
| :--- | :--- | :---: |
| `NLK_CERT_KEY` | 국립중앙도서관 Seoji 인증키 | 선택 |
| `ALADIN_KEY` | 알라딘 TTBKey | 선택 |
| `GOOGLE_API_KEY` | Google API Key | 선택 |
| `GEMINI_API_KEY` | Gemini/LiteLLM API Key (판권지 AI 판독) | 선택 |
| `LITELLM_ENDPOINT` | LiteLLM API 주소 | 선택 |
| `LITELLM_MODEL` | LiteLLM 모델명 | 선택 |
| `STRICT_MATCH` | title 축 검색 결과 엄격한 필터링 | 선택 |
| `ISBN_FILE_SCAN` | 도서 파일(EPUB/PDF) 내부에서 ISBN 검출 시도 여부 | 선택 |

> API 키가 비어 있는 소스는 해당 소스만 자동으로 검색에서 제외되고 나머지 소스로 계속 진행됩니다(구글 제외 모든 소스는 인증정보가 필수).
